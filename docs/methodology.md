# 분석 방법과 보존 자료의 차이

## 생애주기와 예측 유형은 서로 다른 단계

생애주기 분석은 시작~소멸의 기간으로 6개월 미만/이상을 구분합니다. 규칙 기반 예측은 피크 이후 평균 검색량의 하락률을 이용합니다. 여기서 “실제” 유형은 사람이 검증한 외부 정답이 아니라 기존 주기 분석으로 생성한 라벨입니다.

발표자료 7~9쪽은 15% 시작·소멸 조건, 80% 피크 조건과 6개월 분류를 설명합니다. 24~27쪽은 65% 하락률과 분류 가능 표본에 대한 74.1% 정확도를, 29~31쪽은 별도의 랜덤포레스트 결과를 설명합니다.

## 파일 간 차이

| 항목 | 발표자료 | 원본 코드·CSV |
| --- | --- | --- |
| 하락률 기준 | 65% | TXT는 50% |
| 입력 간격 | 1개월 유지, 일부 그래프는 주차 표현 | 웹 원본 CSV 첫 열은 `월`이고 `YYYY-MM` 형식 |
| 연속 구간 | 한 달 이상 | 원본 코드는 연속 4개 관측치 |
| 피크 이후 | 1개월 평균 | 원본 코드는 최대 4개 관측치, 최소 2개 필요 |
| 표본 수 | 100개 밈을 기반으로 프로젝트 설명 | 예측결과 78행, 병합 77행, 실제결과 100행 |
| 예측 결과 | 발표 기준 별도 결과 | 예측결과와 병합 파일의 유형에도 차이 있음 |

월별 데이터에 연속 4개 관측치를 적용하면 4주와 같지 않습니다. 원본 코드에서 `ym()`에 일자를 붙이는 처리와 첫 번째 연속 구간의 인덱스 계산도 점검이 필요합니다.

## 실행용 스크립트의 변경 사항

`archive/예측알고리즘.txt`는 원본 그대로 보존합니다. `scripts/classify_memes.R`는 같은 규칙을 실행하기 위해 다음을 수정한 정리본입니다.

- 사용자 절대경로·Downloads 경로를 저장소 상대경로와 명령행 인자로 변경
- 의존성 설치를 별도 파일로 분리하고 Apple 전용 폰트 설정 제거
- `YYYY-MM`을 직접 `ym()`으로 변환
- 첫 연속 구간이 첫 번째 RLE 구간일 때 이전 길이 합을 0으로 계산
- 출력 CSV 생성에 필요한 부분만 분리; 원본의 원그래프 코드는 TXT에 보존

최댓값의 15% 이상이 연속 4개 관측치인 첫 구간을 찾고, 다시 15% 미만으로 내려가기 전까지 분석합니다. 이 구간에 최댓값의 80% 이상인 관측치가 없으면 제외합니다. 구간 최댓값 이후 최대 4개 관측치의 평균으로 하락률을 계산합니다. 기본 임계값은 50%입니다. 모든 값이 0인 경우에는 데이터 부족으로 처리합니다.

## 성능 해석의 한계

- 전체 시계열 최댓값을 참조하므로 미래 정보가 포함될 수 있습니다.
- 독립 학습/검증/테스트 분할, 교차검증, 무작위 시드가 확인되지 않습니다.
- 발표의 74.1%는 분류 불가능 표본을 제외한 값으로 전체 표본 정확도와 다릅니다.
- 원본 표본 선정과 전처리 전체 이력이 없어 데이터 편향을 배제할 수 없습니다.
- 랜덤포레스트 코드·가중치가 없어 71%를 다시 검증할 수 없습니다.
- 발표의 특정 밈 소멸일 예측은 2025년 당시의 사례이며 실제 소멸 검증 결과는 없습니다.

따라서 결과는 당시 표본에서의 탐색적 분석으로 이해해야 합니다.
